## Clarifications

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 总体三栏式导航与布局浏览 (Priority: P1)

用户进入前端系统后，能看到清晰的三栏/双栏响应式布局（左侧导航树、顶部面包屑与操作栏、中央主工作区），可以顺畅地在不同知识库节点和文档之间切换。

**Why this priority**: 布局是整个前端系统的骨架，决定了所有页面与功能的载入体验和信息架构呈现。

**Independent Test**: 用户启动前端系统后，界面呈现顶部栏、左侧导航侧边栏以及主内容区，点击左侧导航树节点时，主工作区标题与面包屑实时更新。

**Acceptance Scenarios**:

1. **Given** 用户在系统首页，**When** 展开左侧知识库目录树并点击某个文档节点，**Then** 顶部面包屑显示完整层级路径，主工作区更新为该文档的标题与内容。
2. **Given** 用户正在查看文档，**When** 点击左侧边栏底部的折叠按钮，**Then** 侧边栏向左平滑收起为极简图标模式，主工作区自动扩充宽度。

---

### User Story 2 - 顶部全局操作栏与路径导航 (Priority: P2)

用户通过顶部栏实时获知当前上下文位置（面包屑），并能快速执行快捷搜索、快速新建文档/图表、切换阅读/编辑模式以及管理个人设置。

**Why this priority**: 顶部栏承载全局操作和面包屑导向，提升跨文档/跨模块协作效率。

**Independent Test**: 用户在任何层级页面点击顶部面包屑可直接返回上级目录，点击顶部全局快捷操作按钮可触发对应弹窗或动作。

**Acceptance Scenarios**:

1. **Given** 用户位于深层目录 `大沙河跑步1号 > 影视 > 电影`，**When** 点击面包屑中的 `影视` 节点，**Then** 系统跳转至 `影视` 知识库主页。
2. **Given** 用户点击顶部右侧的 `+` 新建按钮，**When** 选择新建文档或新建 Draw.io 图表，**Then** 系统在当前目录下创建一个新节点并载入主工作区。

---

### User Story 3 - 纯粹铺满主工作区与侧边辅助面板 (Priority: P3)

主工作区提供纯粹无干扰的编辑器环境，编辑器直接铺满整个可用空间，并可通过右侧悬浮按钮调出大纲/帮助浮窗。

**Why this priority**: 提供极简纯粹的创作与浏览体验，消除任何不必要的视觉干扰。

**Independent Test**: 打开文档或图表时，编辑画布铺满主工作区；点击右侧大纲图标，悬浮大纲面板平滑浮现。

**Acceptance Scenarios**:

1. **Given** 主工作区加载长文档，**When** 用户点击右侧大纲图标，**Then** 展开目录大纲面板，点击大纲条目可平滑滚动至对应章节。
2. **Given** 用户在编辑内容，**When** 编辑器调整尺寸，**Then** 编辑器画布始终自适应铺满整个主工作区。

---

### Edge Cases

- 当左侧知识库目录树层级极深（如超过 8 层）或节点名称极长时，导航项采用省略号截断并在鼠标悬浮时展示 Tooltip。
- 屏幕宽度缩小至移动端或小屏时（< 768px），侧边栏自动收起为 Drawer 抽屉模式。
- 当主工作区同时载入 Draw.io 图表或文档编辑器时，自适应铺满主工作区容器高度，避免双滚动条。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供顶栏（Header）、左侧边栏（Sidebar）与中央主工作区（Main Content）构成的极简三栏总布局结构。
- **FR-002**: 顶栏必须包含系统标识、层级面包屑（Breadcrumb Navigation）、全局搜索入口、模式切换（阅读/编辑）、快速新建（文档/图表）及用户头像区域。
- **FR-003**: 左侧边栏必须包含主导航菜单（搜索、主页、云盘、知识库、智能工具）、可折叠展开的知识库树状目录（Knowledge Base Tree）、置顶文档区以及底部系统状态/收起控制栏。
- **FR-004**: 系统必须支持侧边栏一键展开/收起切换，并在收起时保留图标直达功能，保持极致简洁风格。侧边栏折叠状态持久化至 LocalStorage。
- **FR-005**: 主工作区必须包含核心编辑器/视图渲染画布以及悬浮的大纲与帮助工具组。
- **FR-006**: 系统必须在窄屏设备下自动切换侧边栏展示模式（抽屉 Drawer），确保自适应布局无溢出。
- **FR-007**: 系统必须支持极简浅色与暗黑无缝切换的样式设计规范，遵循低饱和度、清晰层级与高质感视觉风格。
- **FR-008**: 主工作区必须采用单文档路由与状态替换模式（飞书云文档原生极简风格），点击左侧节点或面包屑直接无缝切换主视图与上下文。
- **FR-009**: 主工作区必须采用全屏铺满无边框结构，移除外层卡片包裹与额外辅助元素（元信息头、模版矩阵），编辑器组件（`my-doc-editor` 富文本或 `Draw.io` 离线画布）直接自适应铺满填充整个主工作区。

### Key Entities

- **LayoutContext**: 布局全局状态实体，管理侧边栏折叠状态、大纲栏显隐、主题模式及当前选中节点信息。
- **NavNode**: 导航与知识库树节点实体，包含 `id`, `title`, `type` (doc | folder | chart), `icon`, `parentId`, `children`, `isPinned` 等属性。
- **BreadcrumbItem**: 面包屑路径实体，包含 `id`, `label`, `path`, `isLast` 状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 布局框架在 1080p、1440p 及常见笔记本分辨率下无横向滚动条，各区域比例和谐美观。
- **SC-002**: 侧边栏折叠/展开动画平滑自然，帧率保持在 60fps，切换无视觉闪烁。
- **SC-003**: 用户在左侧目录树点击切换节点时，主工作区和面包屑更新延迟小于 100ms。
- **SC-004**: 编辑器画布全屏 100% 填充主工作区容器，无额外边距或双滚动条。

## Assumptions

- 视觉风格采用极其简洁的现代云文档风格（如飞书文档/Notion 风格），使用浅灰背景（如 `#F8F9FA` / `#F5F6F8`）、微边框（`#E5E6EB`）与精致字阶体系。
- 编辑器部分复用现有的 `my-doc-editor` 和离线部署的 `Draw.io` 组件，布局层提供自适应容器接入。
- 顶部导航和左侧导航数据暂通过统一的 Navigation State 服务进行管理。
